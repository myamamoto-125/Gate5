# Gate5 · PC貸出管理システム

共用ノートPCの貸出申請・確認・完了・返却を管理する研修用Webアプリです。配布資料の正常系と、例外系洗い出し表No.1〜22を実装しました。GitHubはソース保管先で、アプリはPC上でサーバーを起動して利用します。

![PC貸出申請画面](mocks/mock_00_貸出申請.png)

## 1. 起動手順

Python **3.10以上**とGitを使用します。Pythonの追加パッケージは不要です。

```bash
git clone https://github.com/myamamoto-125/Gate5.git
cd Gate5
python3 app.py
```

Windowsで`python3`がない場合は`python app.py`を使用してください。
ブラウザで **http://127.0.0.1:8000** を開き、サンプル社員を選択して「ログイン」を押します。

|社員ID|氏名|部署|状態・初期データ|
|---|---|---|---|
|1001|山田 太郎|営業部|在職中・貸出なし|
|1002|佐藤 花子|開発部|在職中・貸出なし|
|1003|鈴木 一郎|総務部|休職中・貸出拒否の確認用|
|1004|田中 美咲|企画部|退職済み・貸出拒否の確認用|
|1005|高橋 健|開発部|在職中・PC-0003を貸出中|

サンプル社員ボタンはID・氏名・部署を入力します。照合エラーは手入力で確認できます。社員IDは半角数字、資産番号は半角英大文字・数字・ハイフンのみ。氏名・部署・利用目的は日本語を使用できます。

PC-0001・0002は貸出可能、0003は貸出中、0004は修理中、0005は廃棄済みです。貸出・返却は実データとしてSQLiteに保存され、再起動後も残ります。DBは初回に自動生成します。

### メンテナンス切替

`config.json`の`"maintenance": false`を`true`に変更すると、新規貸出・返却が停止します。**再起動は不要**です。`false`に戻すと再開します。設定が壊れた場合も更新を停止します。既に成功した同一申請の再送は元の結果を返します。

### 別ポート・別DBで起動

```bash
python3 app.py --db demo.sqlite3 --port 8001
```

設定ファイルは`--config`で指定可能。初期データに戻す場合は、元のDBを削除せず別名の新規DBを指定してください。通常起動時にデータを消す処理はありません。

## 2. 洗い出しの結果

- 元の例外表：22件。補完4件を加えた **26件を実装**。
- カバーした観点：①在庫・状態 ②人の状態 ③重複・多重 ④入力値 ⑤順序 ⑥時間 ⑦失敗時 ⑧不正操作、**8カテゴリ**。
- 補完後フロー図の判断：貸出12個＋返却10個、**ひし形22個追加**。
- 返却予定日：必須。当日〜暦上1か月後。月末補正あり。日本時間で判定。
- 期限超過：指定どおり返却を拒否し、開発チームへの連絡を案内。

## 3. 実装した項目・範囲外の項目

全26件の優先度・仕様・テスト対応は[例外系洗い出し表](docs/exceptions.md)を参照してください。

|内容|実装|理由・方式|
|---|---|---|
|正常系の貸出・確認・完了・返却|済|実DBへ保存|
|元の例外表No.1〜22|済|No.20・22の補完解釈は仕様書に明記|
|二重貸出・1人1台・連打・戻る再送|済|書込トランザクション・部分一意制約・確認トークン|
|貸出／返却の複数テーブル更新|済|結果保存も含めて1トランザクション|
|通信切断後の再試行|済|結果不明の案内＋同じ確認トークンで元の結果を再表示|
|サンプル社員ログイン|済|ユーザー指定の研修用方式|
|本番SSO・パスワード認証・管理者権限|対象外|研修用方式のため。現在の簡易ログインは本人認証にならない|
|修理・廃棄のマスター管理UI|対象外|今回の対象は貸出・返却|
|管理者による期限超過の特別返却|対象外|ユーザー指定により通常返却は拒否。開発チームへの連絡までを実装|
|クラウドへのアプリ配備|対象外|依頼されたGitHubへコードを作成。稼働にはPythonサーバーが必要|

## 4. テスト

```bash
python3 -m unittest discover -s tests -v
```

**32件の自動テストに合格**。2人の同時貸出、1人の2台同時申請、同一トークンの8並列再送、貸出・返却それぞれの途中障害とロールバック、日またぎ、CSRF、他人の操作、入力値すり替えを含みます。GitHub ActionsでもPython 3.10・3.12・3.13で実行します。

画面テストと画像再取得は任意です。Node.jsとPlaywrightをインストールし、**別の新規DB**で起動したアプリに対して実行してください。

```bash
npm install --no-save playwright
npx playwright install chromium
python3 app.py --db ui-test.sqlite3 --port 8001
```

別のターミナルで：

```bash
BASE_URL=http://127.0.0.1:8001 node tests/browser.cjs
```

Windowsでは環境変数を利用するシェルの方法で設定してください。`CHROME_PATH`で既存Chrome、`PLAYWRIGHT_MODULE`でPlaywrightのモジュールパスも指定できます。スクリーンショットは実行日のサンプルデータで上書きされます。

## 6. 振り返り

以下は実装から整理した技術上の振り返りです。本人の体験や未提供のGate1振り返りは代筆・推測していません。

- 0件だった観点カテゴリ：なし。8カテゴリすべてを確認。
- 見落としやすい3点：①確認時に空いていても確定前に別の人が借りる、②更新成功後に通信が切れると失敗と断定できない、③確認から確定までに日付が変わる。いずれも1回の画面表示や正常系の手順だけでは観察できず、時系列と同時実行を考える必要がある。
- 増えた確認観点：状態の再検証、業務ルールとDB制約の両方による保証、トランザクションと再送の一体化。Gate1の実際の振り返りとの比較は未提供のため本人による追記欄とする。

研修用アプリは既定でローカルPC内だけで待受けます。サンプル情報によるログインのため、外部公開する場合の本番認証・HTTPS・運用設計は含みません。
